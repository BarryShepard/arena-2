## Important

1. **CPU budget обновляется для каждого события, один tick надолго блокирует UI.** `src/mods/runtime.js:32`, `src/engine/world.js:247`. `evaluate` каждый раз выдаёт новые 8 ms; damage вызывает beforeHit и damageReceived, очередь допускает 1024 items. Даже без превышения отдельного deadline получаются секунды main-thread работы, умноженные на catch-up. Точечный Node probe: P1 отправляет 60 zero-damage команд, P2 в каждом event крутится 2 ms через Date.now; один step занял **242 ms**, `world.error === null`. Это уже выход далеко за frame budget, не теоретическая бесконечность. Нужен общий deadline/оставшийся CPU budget участника на весь tick, включая event callbacks и bridge, а также bounded общий drain. Отдельно `world.js:250` игнорирует configurable events override. Проверить event storm и конфигурируемый event limit. Документирование per-call отличия не исправляет проблему.

2. **Guest может отключить лимит таймеров и менять bridge internals.** `src/mods/runtime.js:46`, `src/mods/bootstrap.js:3`, `src/mods/bootstrap.js:18`. Пользовательский source исполняется в том же lexical scope, что mutable LIMITS, timers, commands и dispatch. Воспроизведение в реальном QuickJS: `LIMITS.timers=1000; defineCharacter({spawn(c){for(let i=0;i<300;i++)c.api.after(1,()=>{});}})` успешно возвращает commands=[] при штатном лимите 256. Runtime heap/interrupt сохраняются, host capabilities не утекли, но обещанный timer budget отсутствует для произвольного мода. Нужны закрытые bridge internals, immutable настройки и независимое enforcement; просто freeze LIMITS недостаточно при доступном `timers.set`. Проверить прямое вмешательство в internals и возможность последующего старта после ошибки.

3. **Невалидный effect ломает host render loop вместо управляемого mod error.** `src/engine/world.js:200`, `src/view/renderer.js:72`, `src/main.js:174`. Host проверяет только positive duration; `api.effect({x:80,y:135,radius:-1,duration:1})` проходит validation (все числа конечны), затем Canvas arc с отрицательным радиусом выбрасывает IndexSizeError. Вызов render вне world try/catch, следующий requestAnimationFrame ещё не назначен: анимационный loop прекращается, Restart не создаёт новый loop. Это вывод по прямому пути кода, browser repro отдельно не запускался. Нужна schema validation всех effect полей до принятия команды и защита frame/render с понятной диагностикой мода и восстановлением. Добавить адресный malformed-effect/restart regression.

4. **Input теряет короткие нажатия и сохраняет состояние предыдущего матча.** `src/engine/input.js:26`, `src/engine/input.js:30`, `src/main.js:48`. Слоты вычисляют edges исключительно между samples: down+up до ближайшего tick полностью теряются. Точечный probe `key('KeyF',true); key('KeyF',false); sample()` возвращает все три флага false. `clear()` очищает только keys, поэтому previous и aim переходят в Restart: после sampled H, clear, нового H следующий sample даёт held=true, pressed=false; новый charge не начинается. После Restart facing первого tick также наследует прошлый бой. Нужен буфер физических slot edges и отдельный полный reset для нового матча (previous, pending events, initial aim). При pause/blur сохранить корректный release для существующего charge. Проверить короткий tap и restart с ранее удержанной способностью.

5. **Кирпичи отсутствуют в spatial API и не перекрывают melee Fighter.** `src/mods/bootstrap.js:9`, `characters/fighter/main.js:13`. queryCircle ищет только entities, хотя Task 1 прямо требует участия solid obstacles в spatial queries. Конкретная геометрия существующей карты: кирпич x=112..144, y=48..112; тела радиуса 7 в (105,100) и (120,119) легальны, distance≈24.2 и попадают в Slash query (24+7), при взгляде вправо проходят sector test, хотя segment между центрами пересекает кирпич. Сам механизм wall blocking отсутствует. Нужен минимальный obstacle-aware query/segment helper и фильтрация Fighter melee по препятствиям, с focused case по обе стороны стены/угла. Полный raycast/projectile pipeline Task 2 не требуется.

## Minor

- **Диагностика host budget errors теряет виновный пакет/игрока.** `src/engine/world.js:123`, `src/engine/world.js:343`: errors из apply/spawn (например Entity budget exceeded) не оборачиваются в manifest id + owner, хотя runtime errors оборачиваются. Добавить контекст вызывающего участника в invoke/apply failure.
- **Browser blur assertion не доказывает очистку input, а foreign-patch test не доказывает автоматический disposal.** `tests/browser-smoke.mjs:103` явно отпускает KeyD после synthetic blur — даже без clear этот keyup очищает движение. `tests/mods.test.js:125` вызывает apply напрямую и затем вручную dispose в finally; тест с названием «stops match and disposes runtimes» проверяет только throw. Сохранить браузерное keydown через blur/resume до assertion и проверять ошибочный мод через world.step с closed-runtime assertion. Browser smoke реально использует public keyboard flow и достигает результата; это не выдуманная проверка, но эти claims шире assertions.

## Что соответствует Task 1

- Раздельные QuickJS runtime, heap/stack/interrupt механизмы есть; моды не исполняются в host realm, bridge передаёт JSON, mirror state разделено.
- FIFO damage/death разрешается до проверки countsForDefeat и затем timeout; 180-second last-tick priority реализован корректно. Pause прекращает step, Restart создаёт новый world. Обычное удерживаемое движение строго по одной оси, last-pressed fallback работает.
- Loader автоматически читает каталог, проверяет API/slots/числа, existing files/signatures, script/package sizes, safe paths и realpath containment; asset decode происходит до матча. Явного path escape в прочитанном loader не найдено.
- Dispose закрывает оба runtime, убирает world queues/effects и останавливает audio sources. Обычный start failure освобождает частично созданный мир. Проблемы input/render recovery перечислены выше.
- Fighter mechanics находятся в моде, engine не знает его имени. Четыре способности и charge state реализованы. Симметричная карта, timer/HUD и lifecycle UI имеются.
